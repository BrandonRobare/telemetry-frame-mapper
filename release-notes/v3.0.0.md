# Telemetry Frame Mapper v3.0.0 — draft release notes

## Breaking API changes

`GET /system/resources` now reports one structured `accelerator` object with `kind`, `device`, display `description`, `splat_backend`, and `splat_backend_available`. The legacy `gpu_available`, `gsplat_available`, `msplat_available`, `splat_training_available`, and top-level `splat_backend` fields, plus `tools[].cuda_available`, were removed. API clients must migrate to `accelerator.kind` and `accelerator.splat_backend_available`.

## Apple-Silicon splat training dependency

Metal training uses the optional, exact pin `msplat==1.1.4` only on arm64 macOS 14+ with Python 3.12–3.13. The package is Apache-2.0 and depends only on NumPy.

msplat is a young, single-maintainer project. It is intentionally isolated in the `splat-metal` dependency group rather than the base or reconstruction groups. If compatible wheels disappear, maintenance stops, or the API breaks, omit that group and preserve the supported `colmap_only` reconstruction path until a reviewed replacement is available. Do not silently broaden the marker, build unreviewed source distributions, or weaken the exact pin.

## Native Metal trainer

On supported Apple-Silicon Macs, accelerator detection now selects msplat automatically; CUDA systems continue to use gsplat. The adapter drives msplat's native adaptive densification loop and synchronizes Metal before progress/completion signals. Before a worst-case native refinement could exceed `max_gaussians`, it checkpoints and reloads with densification disabled, then completes every remaining optimization iteration under the cap. Mid-training cancellation saves both a native msplat checkpoint and a partial viewer-compatible PLY before the reconstruction is recorded as cancelled.
