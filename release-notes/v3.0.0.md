# Telemetry Frame Mapper v3.0.0

v3.0.0 is the cross-platform acceleration release. It adds an arm64 macOS application bundle,
native Apple-Silicon (Metal) Gaussian-splat training, a structured accelerator API that replaces
the CUDA-only fields, and native bundles attached to GitHub Releases. It closes 40 issues in the
[v3.0 milestone](https://github.com/BrandonRobare/telemetry-frame-mapper/milestone/22).

**Metal splat training ships as experimental.** It is validated on one physical Apple M5, and no
CUDA-quality parity or throughput claim is made. See [Metal splat training status](#metal-splat-training-status).

## Breaking API changes

`GET /system/resources` now reports one structured `accelerator` object with `kind`, `device`, display `description`, `splat_backend`, and `splat_backend_available`. The legacy `gpu_available`, `gsplat_available`, `msplat_available`, `splat_training_available`, and top-level `splat_backend` fields, plus `tools[].cuda_available`, were removed. API clients must migrate to `accelerator.kind` and `accelerator.splat_backend_available` (#787).

System Health installation guidance is derived from that accelerator contract. Metal hosts receive the normal PyPI torch command, never a CUDA index or gsplat command; CUDA builds point to the validated toolkit matrix instead of copying a version-blind command; unsupported backends show an explanation without an empty copy action (#788).

## Apple-Silicon splat training dependency

Metal training uses the optional, exact pin `msplat==1.1.4` only on arm64 macOS 14+ with Python 3.12–3.13. The package is Apache-2.0 and depends only on NumPy.

msplat is a young, single-maintainer project. It is intentionally isolated in the `splat-metal` dependency group rather than the base or reconstruction groups. If compatible wheels disappear, maintenance stops, or the API breaks, omit that group and preserve the supported `colmap_only` reconstruction path until a reviewed replacement is available. Do not silently broaden the marker, build unreviewed source distributions, or weaken the exact pin.

## Native Metal trainer

On supported Apple-Silicon Macs, accelerator detection now selects msplat automatically; there is no backend setting. CUDA systems continue to use gsplat. The adapter drives msplat's native adaptive densification loop and synchronizes Metal before progress/completion signals. Before a worst-case native refinement could exceed `max_gaussians`, it checkpoints and reloads with densification disabled, then completes every remaining optimization iteration under the cap. Mid-training cancellation saves both a native msplat checkpoint and a partial viewer-compatible PLY before the reconstruction is recorded as cancelled.

Metal trains the same COLMAP submodel that georeferencing and export use, rather than always `sparse/0` (#855), and exports Gaussians in the original COLMAP coordinate frame rather than msplat's internally normalized one, so GPS annotations, measurements, and PLY-derived GIS points line up (#854).

## Accelerator-aware splat presets

Metal `quick` now runs 1,250 iterations; CUDA remains at 1,000. The value is the smallest preregistered candidate that measurably densified the public 75-view Aukerman survey model (10,883 sparse points to 27,215 Gaussians, 2.501x). A 500,000-cap probe added no detail, so the 350,000 quick cap remains unchanged. See [the benchmark record](https://github.com/BrandonRobare/telemetry-frame-mapper/blob/v3.0.0/docs/benchmarks/metal-quick-preset.md).

Accelerator policy fills only preset fields omitted from `config.yaml`; every explicitly configured value wins. Reconstruction status and Jobs now retain and display the actual accelerator, selected splat backend, iteration count, Gaussian cap, and complete effective trainer settings (stored by migration `0017`). CPU-only jobs report `COLMAP only` rather than claiming CUDA (#820).

## Metal splat training status

- **Experimental.** No CUDA-quality parity or throughput claim is made. In a source checkout, omit `splat-metal` for production work; reconstruction then completes as the supported `colmap_only` result. The macOS release bundle includes msplat and always trains with Metal on a supported Mac; it has no setting to turn training off.
- **Validated hardware.** Two early held-out runs on GitHub-hosted Apple M1 (Virtual) runners exported non-finite Gaussians (10,194 of 25,225 and 4,869 of 27,362 rows). Three fresh runs of the same fixture on a physical Apple M5 exported zero, and #849 was closed on 2026-09-13 as not reproducible on the supported target. Other physical Apple-Silicon chips are untested.
- **Fail-safe.** Every Metal export is validated before the reconstruction is recorded: means, scales, quaternions, opacities, and all SH coefficients must be finite, exponentiated scales must not overflow, quaternion norms must be non-zero, and the written row count must match the trainer's. Invalid output fails the job; the artifact is kept for diagnosis and rows are never silently dropped (#851).
- **Release gate.** A tag build now requires a native msplat training run through the product `quick` preset on the physical M5, validated in a fresh process; one invalid row blocks publication. The manual proof produced 24,596 Gaussians with zero invalid rows (#852).
- **Parity not measured.** The preregistered CUDA–Metal held-out harness merged on 2026-09-25 (#848), but its CUDA leg (#853) and the PSNR/SSIM verdict (#784) have not run because no NVIDIA host is available. Both are deferred to a later release.

## macOS application bundle

- New arm64 `Telemetry Frame Mapper.app` built with PyInstaller (#786). It is ad-hoc signed only (no Developer ID) and not notarized. First launch creates `~/Library/Application Support/Telemetry Frame Mapper/` for configuration, the database, imports, processed files, and exports.
- Build, smoke test, Finder launch, Homebrew tool discovery, import, geotagging, and a COLMAP reconstruction were verified on a physical Apple M5 running macOS 27.0 (#817).
- A Finder-launched bundle finds Homebrew `ffmpeg`, ExifTool, and COLMAP in `/opt/homebrew/bin` and `/usr/local/bin` (#816). Set `TFM_EXTRA_TOOL_ROOTS` (colon-separated) for MacPorts or a custom prefix (#877).
- Launching the bundle opens the UI in the default browser once the server is listening; a second launch focuses the running instance instead of failing to bind the port (#833). This applies to the Windows bundle too.
- The supported floor for the full feature set is Apple Silicon, macOS 14 or later, and Python 3.12 or 3.13. Outside it, a source checkout runs everything except Metal training; the bundle itself is arm64-only (#818). See `docs/INSTALL.md` and `docs/PLATFORM-MATRIX.md`.
- On Metal-only hosts, semantic segmentation defaults to CPU; MPS is used only when selected explicitly (#825).
- CI builds and smoke-tests the arm64 bundle on every run (#789), release publication requires that job (#790), and the smoke launches the app with a bare `PATH` and fails unless ffmpeg and ExifTool are still discovered (#832).

## Release assets

Tagged releases now attach native bundles built by the release's own CI run, alongside `frontend-dist.zip` (#869):

- `macos-arm64-bundle.zip` — the zipped `.app`, with a `.sha256` checksum file.
- `windows-x64-bundle.zip` — the zipped PyInstaller application folder. It is **not** the Inno Setup installer: there is no setup program or Start-menu entry. Unzip it and run `Telemetry Frame Mapper.exe`; data is stored under `%LOCALAPPDATA%\Telemetry Frame Mapper\`. Building the installer is still the local step in `docs/WINDOWS-INSTALLER.md`.

Neither bundle carries a publisher signature.

## Reconstruction and deployment

- COLMAP 4.x: guided matching and the global mapper use the 4.x option namespaces; on Homebrew COLMAP 4.1.1 both previously failed before starting. Pre-4.0 binaries keep the old options (#856). GPS spatial matching no longer passes the `is_gps` flag COLMAP 4.1 removed (#820).
- The Docker image now installs the `semantic` dependency group that per-frame semantic segmentation needs (#872).
- Semantic segmentation no longer crashes when Transformers returns entries with `score=None` (seen on CPU with `transformers` 5.x); confidence is derived from mask coverage (#844).
- Hosts where gsplat imports but cannot run now complete as `colmap_only` instead of failing mid-training, and System Health reports such a backend as unavailable (#779, #822). Splat thumbnails are skipped and server-side flythrough rendering points to browser recording when no CUDA renderer is usable (#815).

## Fixes

### Import and review

- Thumbnails resolve through `GET /images/{id}/thumb`, so absolute thumbnail paths (normal for the macOS bundle) display in Review and on defects (#857). An absolute thumbnail path outside `processed/` no longer returns 500 (#876).
- New thumbnails are named `<image id>_<filename>`, so case-variant siblings such as `IMG.JPG` and `img.jpg` no longer overwrite each other on case-insensitive macOS volumes (#831).
- The browser import drop-zone names the non-JPEG files it skipped instead of dropping them silently (#865).
- The post-import Quick QA summary now appears after a server-path import, and a failed import keeps its error details in the modal (#860).

### Frontend reliability

- A malformed status event no longer stops live job updates (#866).
- A browser import whose `/complete` call succeeded is never cancelled by a later network error (#867).
- API requests time out after 120 seconds instead of leaving the UI pending forever on a stalled backend (#868).

### Source launchers

- `dev.sh`/`dev.bat` pass `VITE_API_URL`, so the dev frontend reaches its backend instead of rendering an empty app (#803).
- The dev launchers sync with `uv sync --inexact`, so starting them no longer uninstalls optional groups such as `reconstruction` (#858), and install the frontend with `npm ci` (#873).
- `run.sh` and `run.bat` stop the frontend when the backend exits, instead of leaving a dead UI on port 5173 (#862, #874).

## Security

- CSV exports neutralize spreadsheet formulas: text cells starting with `=`, `+`, `-`, `@`, tab, or carriage return get a leading `'` in measurement CSVs, control-point CSVs, and the CLI audit CSV (#863).
- `POST /uploads/imports/start` returns 409 while eight browser-import reservations are in flight, so a LAN client cannot exhaust disk with empty reservations (#864).
- `anyio` 4.14.2 fixes CVE-2026-63374, CVE-2026-64847, and CVE-2026-63349 (#916).
- CodeQL fixes: out-of-coverage CRS warnings no longer log flight coordinates or the configured CRS (#917); session archive, archive restore, and atomic export ZIPs reject parent traversal, backslashes, and symlinks beneath a configured root (#918); reproducibility-manifest artifact reads cannot follow a swapped symlink out of a trusted root (#919); share-bundle writes are anchored to their directory and reject symlinked artifacts (#920).

## Upgrading

- **API clients** that read `/system/resources` must switch to the `accelerator` object; see [Breaking API changes](#breaking-api-changes).
- **Migration `0017`** adds one nullable column, `reconstructions.effective_splat_settings`. It is additive and has a working downgrade. The pre-migration database snapshot introduced in v2.0.5 runs first.
- **Node.js 22.12 or later** is required to build the frontend from source; `frontend/package.json` declares it in `engines`. npm warns on older versions but does not block. CI and the Docker image use Node 22 (#834, #875).
- **Explicit quick iterations.** In a source checkout, a `config.yaml` that still sets `reconstruction.presets.quick.iterations` (the v2 default was `1000`) keeps that value on Metal; delete the line to get the 1,250-iteration policy. Saving the Splat Training settings page writes every preset field, including the displayed iterations, so it sets the value explicitly too.
- **Bundled-app configuration** (macOS and Windows bundles only). On every launch, the app-data `config.yaml` is reconciled with the bundle's default `config.yaml`: stored values for keys that still exist are kept, new keys get their defaults, and keys that are not in the bundled defaults are removed. When anything is removed, the previous file is copied to `config.yaml.legacy`, replacing any earlier copy. The rewrite drops YAML comments. Keys removed this way include valid ones the defaults omit, such as `deployment.auto_open_browser` and `reconstruction.presets.quick.iterations`. An unreadable config is left untouched. Source checkouts and Docker are unaffected (#871).
- **Removed preset keys.** `GET /settings` now returns only the `quick` and `full` presets (#908). In a source checkout, a stale key inside a preset, such as v2.0.5's removed `max_frames`, is still echoed until you delete it by hand; the bundled apps remove it through the reconciliation above.
- Upgrade the whole source checkout or bundle; `frontend-dist.zip` alone does not install backend, migration, or packaging changes. Back up the database, `config.yaml`, and required artifacts first.

## Known boundaries

- Metal splat training is experimental and validated only on a physical Apple M5.
- Neither the CUDA baseline (#853) nor the CUDA–Metal quality verdict (#784) has run; both are deferred.
- Per-Gaussian semantic labeling and server-side flythrough rendering still require CUDA.
- The macOS bundle is arm64-only, neither bundle carries a publisher signature, and the macOS bundle is not notarized. The hardware gate (#817) used a locally built bundle, so Gatekeeper behaviour for a downloaded copy is untested.
- The Windows release asset is built without the `reconstruction` dependency group (`laspy`, `rasterio`), so LAS, orthomosaic, and elevation exports are unavailable in it. Neither bundle includes the `semantic` group.
- On Windows, a reproducibility manifest that names an artifact returns 422 instead of hashing it, because the hardened read needs descriptor-relative opens Windows lacks (#919).
