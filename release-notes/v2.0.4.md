# Telemetry Frame Mapper v2.0.4

v2.0.4 is a subsystem-correctness release for defects found after v2.0.3 across the
reconstruction pipeline, raster and point-cloud export, storage lifecycle, browser uploads, the
frontend, and the CLI. It does not add a new product surface. Every one of the 52 closed issues
in this milestone shipped with a regression test.

## Fixed

### Reconstruction and splat pipeline

- Trained the splat on the same COLMAP sub-model the geo-transform is derived from, instead of always `sparse/0` (#624).
- Recorded splat training failures as failures rather than as a successful `colmap_only` reconstruction (#625).
- Stopped `render_flythrough` deadlocking on ffmpeg stderr while holding the global GPU lock, and made it honour its cancel Event so an in-flight render can be stopped (#626, #733).
- Reported a failed splat-transform subprocess as an error instead of `201 Created` (#645).
- Routed semantic labelling through the GPU-capped job queue and stopped it loading full-resolution views outside the GPU lock (#634).
- Prevented a job-queue retry from resurrecting a cancelled job (#630).
- Made the `quick` preset actually select the COLMAP matcher and removed the dead `exhaustive_matching` key it was reading (#667).

### Export and raster correctness

- Preserved colour in orthomosaic export, which previously always produced a flat grey mask (#627).
- Wrote orthomosaic output atomically so a crash no longer wedges the export permanently, and indexed raster rows from `y_max` instead of truncating toward zero, which shifted the raster north (#628, #636).
- Generated `gcp_list.txt` in ODM's actual format, without shifting columns when altitude is absent (#629).
- Bounded LAS point-cloud export, which allocated 4–12 GB per chunk (#633).
- Applied the elevation export's minimum-resolution guard before the computation it protects (#639).
- Derived the footprint UTM zone from the flight instead of one fixed zone, and surfaced projection failures instead of swallowing them (#640).
- Built share-bundle and USD ZIPs atomically inside their export root, so concurrent requests cannot corrupt them, and stopped concurrent reconstruction bundle downloads corrupting each other (#641, #684).
- Answered WMS `GetCapabilities` before an orthomosaic exists rather than returning 409 (#682).
- Surfaced DEM sampling failures instead of silently substituting ground elevation zero (#646).

### Storage lifecycle and data integrity

- Made the disk-pressure rule delete raw frames as intended instead of archiving them and freeing nothing, and gave storage policy rules an explicit archive/delete action (#642).
- Escaped `LIKE` session matching, which could match by substring and delete fresh data (#643).
- Cleared reconstruction paths in the database when the storage sweep removes the artifacts (#644).
- Validated `TargetArea` geometry on write instead of 500-ing three downstream consumers (#638).
- Skipped short rows in `parse_dji_csv` the way its sibling parsers already did, instead of crashing (#683).

### Browser uploads and remote transfers

- Bounded browser-upload chunk reads before allocation, serialized quota reservation across concurrent starts under one lock, and made upload completion idempotent (#585, #601, #602).
- Streamed WebODM downloads and Cesium ion uploads instead of buffering whole artifacts in memory (#637).

### Backend reliability and performance

- Bounded the flight-log offset preview's iteration count and stopped it re-sorting on every call (#635).
- Indexed the foreign-key columns actually used as query filters (#648, migration `0016`).
- Served the status SSE stream from an async generator so each connection no longer pins an anyio worker thread (#650).
- Consolidated path confinement onto one guard outside the reconstruction service (#647).
- Held the single-process contract for share-link unlock throttling when PIN lock is disabled (#652).
- Routed `dev.sh` and `dev.bat` through the validated deployment bind they previously bypassed (#632).

### Frontend

- Taught the frontend the `running_remote` status, so remote reconstructions no longer look idle (#655).
- Cleared the Splat Viewer when switching sessions instead of leaving the previous session's model on screen (#656).
- Scoped render errors to the failing tab, so one tab can no longer blank the whole application (#649).
- Fit map bounds once per session rather than on every live poll, so the operator can pan during an import (#662).
- Kept the slope overlay after leaving the Map tab by not caching a revoked blob URL (#663).
- Stopped splat-viewer orbiting from re-rendering the whole application on every pointer move (#664).
- Searched job history across a window instead of only the loaded page, which reported false "no match" (#665).
- Removed the Heatmap and Target Area layer toggles the map never rendered (#666).
- Inlined computed styles when serializing the profile SVG, which previously lost every stroke on export (#681).

### CLI correctness

- Made `dvg-pipeline` execution status truthful for every step (#583).
- Kept partially-matching SRT blocks and accepted DJI's `longtitude` spelling instead of dropping them silently (#674).
- Stopped treating a bare absolute altitude field as relative, which double-counted takeoff elevation (#675).
- Re-applied the UTF-8 filename charset at each ExifTool `-execute`, not only the first frame (#676).
- Read job specs and SRT files as UTF-8 rather than the locale codec (#677).
- Reported real GPS presence during pipeline ingest when `piexif` is absent, instead of marking every image GPS-less (#678).
- Converted the audit CSV `utc_timestamp` column to actual UTC so it agrees with the written EXIF (#679).
- Selected the subtitle stream for SRT extraction instead of hardcoding `0:2` (#685).

### CI

- Ran the Windows-sensitive pytest suites on Windows in CI, not only the packaging smoke (#651).

## Upgrade

1. Stop the backend and create a complete pre-upgrade copy of the SQLite database, `config.yaml`, and any required `imports`, `processed`, and `exports` data. The Storage backup workflow can create a checksummed snapshot when configured.
2. Upgrade the whole source checkout or Windows installation to v2.0.4. Replacing `frontend-dist.zip` alone does not install backend, CLI, migration, or packaging fixes.
3. For a source checkout, run:

   ```bash
   git fetch --tags
   git checkout v2.0.4
   uv sync --frozen --group backend --group reconstruction --group dev
   cd frontend && npm ci && npm run build
   ```

4. Restart one API process. Startup applies migration `0016`, which creates 13 indexes on existing foreign-key columns. It is additive and creates no columns or tables. Release rehearsal measured the upgrade at 85 ms on a 400,000-image, 50 MB database, so no meaningful startup delay is expected. Confirm `/health`, open the application, and verify the expected projects and sessions before deleting the pre-upgrade backup.

If your `config.yaml` still carries the `reconstruction.presets.*.exhaustive_matching` keys removed in #667, no action is required: preset merging is permissive, so the stale key is ignored rather than rejected.

## Rollback

The supported rollback is a full pre-upgrade restore, not an in-place database downgrade:

1. Stop every Telemetry Frame Mapper API process.
2. Preserve the failed v2.0.4 state separately for diagnosis.
3. Restore the pre-upgrade SQLite database, configuration, and required artifact directories from the snapshot created before upgrade.
4. Restore the v2.0.3 source checkout or installer, synchronize its dependencies/build, and start exactly one API process.
5. Confirm `/health`, project/session visibility, and representative artifact access before resuming writes.

Migration `0016` does define a working `downgrade()` that drops only the indexes it created, so reverting application code does not require destructive schema surgery. Release rehearsal exercised the full `0015` -> `0016` -> `0015` cycle against a synthesized pre-upgrade database and confirmed the upgrade is idempotent on re-run and that row counts are unchanged in both directions. Restoring the pre-upgrade snapshot remains the supported path because it also reverts any post-upgrade data changes. Never test rollback for the first time on the only production copy.

## Verification

The exact release candidate runs the complete reusable verification workflow before publication is allowed: the Python suite on 3.11 and 3.12 with the locked backend, reconstruction, dev, and audit groups; a `pip-audit` of locked runtime dependencies; ruff; the frontend lint, test, and build; Docker image build with an unauthenticated-LAN-bind rejection check and container health smoke; a clean-environment wheel CLI smoke; and the Windows package build with startup and migration smoke.

## Known boundaries

- GPU reconstruction paths changed in this release (#624, #625, #626, #634) are covered by the automated suite with mocked CUDA libraries. They were not exercised on real GPU hardware for this release; COLMAP, gsplat, SuGaR, and server-side video rendering remain manual checks.
- PIN/share sessions and throttles remain process-local; run one API process on one host.
- The published Python wheel remains CLI-only. Use a source checkout, Docker, or the Windows installer for the web application.
- GPU reconstruction capability still depends on the separately documented COLMAP, CUDA, torch, and gsplat setup.
