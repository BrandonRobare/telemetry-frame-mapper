# Telemetry Frame Mapper v2.0.3

v2.0.3 is a maintenance release for blocking correctness, data-integrity, deployment, and release-verification defects found after v2.0.2. It does not add a new product surface.

## Fixed

### Data integrity and backend reliability

- Added the missing Alembic ownership for orthomosaic and footprint columns so existing databases upgrade to the current model schema (#621).
- Recovered stranded reconstruction rows after worker crashes and terminalized queued cancellations (#622).
- Rejected non-positive altitude and bounded lane generation before mission planning can hang or exhaust the backend (#623).
- Preserved atomic settings writes and response reads under concurrent Windows file-sharing behavior (#587, #653).
- Confined project import paths, routed project deletion through session cleanup, and bounded/atomically promoted restored session archives (#584, #600, #603).
- Made nested browser imports recursive without basename collisions and corrected the GPS flight-log multipart contract (#595, #596).
- Generated battery-segment KML and GPX downloads from the selected segment instead of the full mission (#597).

### Deployed app and frontend

- Centralized browser API, media, upload, download, and event-stream URLs on a same-origin-aware resolver (#586).
- Kept token-authorized share views and their required static shell assets usable under PIN lock while non-share routes remain protected (#604, #631).
- Rejected Docker's default unauthenticated LAN bind unless authentication or the explicit override is configured (#598).
- Omitted malformed persisted mission geometry instead of crashing the application (#605).
- Rendered cancelling jobs safely, invalidated stale storage dry runs after rule edits, and required confirmation before clearing Review selections (#654, #657, #658).
- Added a non-cryptographic browser-local ID fallback for toasts and checklist items on insecure LAN origins (#659).

### CLI correctness

- Preserved no-fix telemetry intervals and refused to interpolate frames across unknown GPS positions (#670).
- Encoded below-sea-level altitude with the correct EXIF altitude reference (#671).
- Compared inferred frame timing with actual video duration and reported the `--frame-rate` remedy on disagreement (#672).
- Accepted negative and positive UTC offsets, compact offsets, `Z`, space-separated timestamps, and bare creation times (#673).

### Packaging, documentation, and release safety

- Isolated pytest databases, made the wheel's CLI-only contract explicit, and bundled Alembic assets into the Windows application (#591, #599, #608).
- Made `uv.lock` authoritative for CI and Docker, audited locked runtime groups, pinned release actions, and required the complete reusable verification workflow before publication (#592, #607, #609).
- Corrected source-development dependency-group instructions and the documented PIN/share trust boundary (#660, #661).
- Applied compatible pinned Python and frontend dependency updates (PR #581).

## Upgrade

1. Stop the backend and create a complete pre-upgrade copy of the SQLite database, `config.yaml`, and any required `imports`, `processed`, and `exports` data. The Storage backup workflow can create a checksummed snapshot when configured.
2. Upgrade the whole source checkout or Windows installation to v2.0.3. Replacing `frontend-dist.zip` alone does not install backend, CLI, migration, or packaging fixes.
3. For a source checkout, run:

   ```bash
   git fetch --tags
   git checkout v2.0.3
   uv sync --frozen --group backend --group reconstruction --group dev
   cd frontend && npm ci && npm run build
   ```

4. Restart one API process. Startup applies the additive `0015` migration. Confirm `/health`, open the application, and verify the expected projects and sessions before deleting the pre-upgrade backup.

Upgrade verification for this release exercised a legacy-like SQLite database with the four missing columns removed, ran the real startup migration to Alembic head, and compared every resulting table with current SQLAlchemy model metadata. The exact candidate also runs Linux and Windows verification, Windows startup/migration smoke, Docker startup/health, and clean-wheel CLI smoke before publication is allowed.

## Rollback

The supported rollback is a full pre-upgrade restore, not an in-place database downgrade:

1. Stop every Telemetry Frame Mapper API process.
2. Preserve the failed v2.0.3 state separately for diagnosis.
3. Restore the pre-upgrade SQLite database, configuration, and required artifact directories from the snapshot created before upgrade.
4. Restore the v2.0.2 source checkout or installer, synchronize its dependencies/build, and start exactly one API process.
5. Confirm `/health`, project/session visibility, and representative artifact access before resuming writes.

The only v2.0.3 schema change is additive and nullable, so reverting application code does not require destructive column removal. Restoring the pre-upgrade snapshot remains the verified path because it also reverts any post-upgrade data changes. Release preparation verifies the backup/migration/restore sequence against a disposable legacy-like database; never test rollback for the first time on the only production copy.

## Known boundaries

- PIN/share sessions and throttles remain process-local; run one API process on one host.
- The published Python wheel remains CLI-only. Use a source checkout, Docker, or the Windows installer for the web application.
- GPU reconstruction capability still depends on the separately documented COLMAP, CUDA, torch, and gsplat setup.
